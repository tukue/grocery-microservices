# Data Model: Authenticated Grocery Customer Journey

The feature introduces no new authoritative grocery domain database. Product, cart, and order data remain owned by their existing services. The BFF adds transient session state and the browser adds transient checkout-attempt state.

## Session

Server-side BFF record representing one authenticated browser session.

| Field | Type | Rules |
|---|---|---|
| `id` | opaque string | Cryptographically random, unique, never reused, stored in cookie only |
| `jwt` | string | Returned by identity provider; never returned to browser scripts |
| `userId` | string | Derived from validated identity claims |
| `email` | string | Derived from validated identity claims; normalized for display |
| `expiresAt` | timestamp | Must not exceed upstream token validity |

**State transitions**: `absent -> active` on login; `active -> expired` at expiry; `active/expired -> absent` on logout or cleanup.

## Product

Authoritative catalogue item owned by product-service.

| Field | Type | Rules |
|---|---|---|
| `id` | positive integer | Stable product identifier |
| `name` | non-blank string | Searchable display name |
| `description` | non-blank string | At most the service limit |
| `price` | positive decimal | Display value only outside product/order services |
| `currency` | string | Three uppercase ISO 4217 letters |
| `available` | boolean | Controls whether add-to-cart is offered |
| `stockQuantity` | non-negative integer | Service-owned availability input; may be omitted from browser response |
| `imageUrl` | URL or null | Optional display image |

## Cart

Current mutable basket owned by one authenticated customer.

| Field | Type | Rules |
|---|---|---|
| `id` | positive integer | Generated by cart-service |
| `customerId` | string | Derived from bearer identity; not accepted from browser |
| `status` | `OPEN` or `CHECKED_OUT` | Only `OPEN` carts may be mutated or submitted |
| `items` | list of Cart Item | May be empty before checkout |

**State transitions**: `absent -> OPEN` on creation; `OPEN -> OPEN` on item mutation; `OPEN -> CHECKED_OUT` when order-service successfully claims the cart. Compensation may reopen a claimed cart if downstream order creation fails.

## Cart Item

| Field | Type | Rules |
|---|---|---|
| `id` | positive integer | Unique within persistence |
| `productId` | positive integer | Must identify a current product |
| `productName` | non-blank string | Server-provided display value |
| `price` | non-negative decimal | Server-provided current unit price |
| `quantity` | positive integer | Must satisfy validation and available stock |

**Relationships**: Many cart items belong to one cart; each references one product.

## Checkout Attempt

Transient browser/BFF representation of a request to convert one cart into an order.

| Field | Type | Rules |
|---|---|---|
| `cartId` | positive integer | Must be the current customer's open cart |
| `idempotencyKey` | opaque string | Generated internally, maximum 64 characters, reused only for retries of the same attempt |
| `state` | enum | `READY`, `SUBMITTING`, `AMBIGUOUS`, `SUCCEEDED`, or `FAILED` |

**State transitions**: `READY -> SUBMITTING`; `SUBMITTING -> SUCCEEDED` on confirmed response; `SUBMITTING -> AMBIGUOUS` on timeout/unknown outcome; `AMBIGUOUS -> SUBMITTING` with the same key; `SUBMITTING -> FAILED` for a definitive rejection. A material cart change after rejection creates a new key.

## Order

Durable purchase record owned by order-service.

| Field | Type | Rules |
|---|---|---|
| `id` | positive integer | Generated by order-service |
| `userId` | string | Authenticated owner; never trusted from browser input |
| `cartId` | positive integer | Source cart; one order per successful checkout result |
| `status` | `PENDING`, `COMPLETED`, or `CANCELLED` | Existing service lifecycle |
| `orderDate` | timestamp | Set by order-service |
| `total` | non-negative decimal | Derived from persisted order lines |
| `orderLines` | non-empty list of Order Line | Snapshot at checkout |

**Relationships**: One order belongs to one customer, references one source cart, and contains one or more lines.

## Order Line

| Field | Type | Rules |
|---|---|---|
| `productId` | positive integer | Product reference at purchase time |
| `productName` | non-blank string | Purchase-time display snapshot |
| `unitPrice` | non-negative decimal | Purchase-time authoritative price |
| `quantity` | positive integer | Purchased quantity |
| `lineTotal` | non-negative decimal | `unitPrice * quantity`, calculated by the service |

## Ownership and Trust Boundaries

- Product-service owns availability and catalogue price.
- Cart-service owns current cart state and cart ownership.
- Order-service owns checkout idempotency, cart claiming, recorded prices, totals, and order ownership.
- The BFF owns the browser session-to-token mapping and route allowlist.
- The browser owns only presentation state and the retry key; it does not own identity or monetary truth.
